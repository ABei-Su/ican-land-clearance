# 靶标识别性能优化 2026-10-20

目标：减少每帧靶标相似度计算的重复开销，保持原有识别和发射判定。

原实现对每个候选四边形，逐一比较八个编号和四种旋转。新实现启动时缓存模板的四方向 5×5 码元，使用 NumPy 批量比较，继续按相似度和编号倒序排序。0.84 相似度下限、0.06 第一第二候选差值、图像处理与候选几何筛选均未改变。没有新增依赖、修改 ROS 接口、导航参数、发射门限或官方场景。

等价依据：对方形二值矩阵，旋转观测与固定模板的相等元素数，等于固定观测与反向旋转模板的相等元素数；四方向集合相同。新旧实现均以 25 个码元的相同比例评分，保留同分编号排序。

测试覆盖全部官方编号四方向、每位翻转噪声、随机码图、重复模板的同分竞争，以及缓存对原始模板的独立性。40 项仓库测试通过，日志 reports/optimization-20261020/tests.log。

性能比较使用七张真实记录图像，每个版本预热五轮、测量二十轮共 140 次，交替先后顺序，OpenCV 固定单线程。新旧所有编号、中心、角点、置信度完全相同。中位数 1.927044 ms → 1.1610255 ms，约减少 39.75%，加速比 1.660。结果只适用于此次图像集的检测耗时，不能解释为整场任务提速。证据 reports/optimization-20261020/benchmark.json。

首次集成运行 0e541c540321 在第一观察点末段校正时因里程计超过 2 秒未更新而终止；未调用识别评分或射击。记录保留，安全超时不放宽。原因尚未确认。

第二次带窗口运行 e0797cc4893c 同样在仿真时间 12.6 秒终止。关闭官方 GUI 的对照 ed66e8ba2c34 完成前两点、记录固定靶和正确旋转靶 ID 2 的碰撞，但在第三观察点的仿真时间 74.3 秒再次出现里程计中断，仿真时钟同时停止推进。运行中 CPU/内存压力较低、UDP 接收丢包计数为零；不能归因于单独的图形客户端或识别算法。

独立静态审查未发现旋转最大值、同分排序、评分精度、拒绝门限或数组所有权的问题。审查没有替代运行测试。
